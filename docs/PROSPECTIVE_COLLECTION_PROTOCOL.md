# Deterministic prospective collection protocol

Version: india-delayed-eod-0630-v1. First eligible canonical origin session: 2026-10-09; first cutoff: 2026-10-10T01:00:00+00:00. This is a new canonical origin group; the388forecasts from prospective-india-20261008-v1 remain legacy intraday/manual research and are never pooled with this group. Frozen universe, models, selection, calibration, OOD and abstention remain unchanged. No successor final model or production promotion is authorized.

## Canonical origin and timing

Session D is an eligible NSE capital-market equity session. The prediction information cutoff is exactly06:30Asia/Kolkata on calendar day D+1 (01:00UTC). Input acquisition window is06:00inclusive to06:30exclusive; generation/finalization is06:30inclusive to07:00exclusive. This is a delayed after-close research origin, not an intraday origin. The delay is deliberate: audited free-feed same-day EOD candles sometimes lacked final Close/AdjClose; the frozen model consumes completed daily bars and delayed global references. Overnight acquisition permits final Indian data and prior global closes without changing its feature recipe. The cutoff never slides to retry/provider completion time.

Two scheduler invocations perform capture before the cutoff and finalize after it. Page views/HTTPGET/refresh never issue predictions or run collection. An eligible session is identified by a versioned official calendar, not by whether a user opened the app or whether one stock happened to return quotes. All timestamp storage is awareUTC; market/session interpretation is Asia/Kolkata.

Regular sessions use the published09:15–15:30IST schedule. Weekends and official trading holidays are ineligible except explicitly documented special sessions. Special sessions require an official date/open/close override; an announced special session with unconfirmed timing fails closed as CALENDAR_UNCONFIRMED. Unknown calendar years are also unavailable, not guessed as weekdays. Calendar updates are new versions with source references, raw source hashes and audit events; existing batches retain the calendar identity used at issuance. The initial2026calendar uses NSE's holiday endpoint, CMTR71775, the January15addendum CMTR72260 and February1special-session circular CMTR72349. November8Muhurat timing remains unconfirmed until its timing circular is registered.

## Input acquisition and retries

Capture the entire fixed100-member universe and all configured contextual sources. Preserve raw provider-normalized OHLCV, AdjClose, dividends/splits, exchange timezone, provider/version, actual retrieval and session-observation timestamps, including invalid/missing fields. This is not a claim of raw HTTP-packet capture or verified historical publication times. Snapshots are immutable content-addressed files; new revisions receive new IDs.

Each source permits at most3attempts, delays0/20/60seconds, timeoutbounded by the remaining acquisition window. Stock/reference failures record ticker/source, stage, code, actual timestamp, attempt count, retry status and sanitized reason. No success-shaped fallback, stale substitution, infinite retry or acquisition after06:30is admitted. A source still unavailable at the cutoff is unavailable for that origin permanently. Provider errors and missing/invalid candles remain visible for every stock; optional references may degrade health when the frozen schema does not require them. A required trained feature family missing prevents that forecast.

Only quotes fully completed by their own retrieval time and the fixed cutoff enter the feature vector. The stock's final complete daily session must equal D; all canonical forecasts use that exact origin price/session. Original feature construction and frozen native heads are reused without fitting or recalibration. Every generated record retains actual generated time, fixed information cutoff, current/price timestamp, origin session/group, protocol/universe/calendar/model/feature/code identities, sources/snapshots, full feature vector, raw/issued/calibrated probabilities, quantiles, confidence/OOD/reasons and research semantics.

## Deterministic identity, concurrency and recovery

Batch ID is UUIDv5(protocolversion, origin session D, fixedcutoffUTC, frozenmodelversion, universehash). Prediction ID is UUIDv5(protocolversion, ticker, fixedcutoffUTC, horizon, modelversion). Horizons are1/5/10/20eligible sessions. One protocol identity pins one universe, calendar version and model artifact set; incompatible changes need a new protocol version.

Control state and immutable research payloads are separate. SQLite transactions serialize admission and deterministic IDs enforce uniqueness. Capture attempts and lifecycle events append; forecasts/outcomes/sealed batches reject updates/deletes. Per-stock four-horizon records commit atomically. Before sealing, partial internal records are not exposed as a completed public batch. A process restart within the generation window verifies stored hashes and processes only missing stocks against the already-frozen pre-cutoff inputs. It cannot recapture after the cutoff. On deadline, missing stocks receive explicit failure status; previously inserted records remain unchanged. After a valid batch is sealed, reruns report ALREADY_EXISTS, verify integrity and perform no provider/inference or forecast/snapshot/batch writes. A separate operational DUPLICATE_PREVENTED event may append.

A sealed batch has a status for all100members, one immutable manifest, per-stock successes/failures, all source attempts, start/finish times, snapshot/feature/parameter/artifact hashes, duplicate/resumption events and health. HEALTHY requires100stocks/all400horizons, valid required data and no provider/quality failures. DEGRADED means some valid forecasts plus visible missing/failed/degraded inputs. FAILED means no eligible forecasts or an integrity/system failure. SKIPPED represents a confirmed non-session and is distinct from healthy. Job process exit0 alone does not imply HEALTHY.

## Outcome maturity and metric conventions

The independent resolver uses the registered official calendar to find the exact D+h session, never the hth available candle. It captures new outcome stock/benchmark/sector sources, then admits an endpoint only after that source's actual receipt follows the registered session close plus20-minute delivery margin. Missing/non-traded/nonfinite stock endpoints or unavailable benchmark endpoints remain pending; future values and stale pre-close captures are rejected. Original predictions remain immutable; realized outcomes append once with their own content hash and source IDs. Existing388legacy forecasts may mature in their legacy ledger/group, with original payload hashes verified, and remain separate from canonical evaluation.

Cumulative return and model error use vendor total-return AdjClose endpoint ratios: logreturn ln(adjusted_end/adjusted_origin); arithmetic return exp(logreturn)-1. Raw final Close is reported separately. Price-error metrics against implied raw price are nullable when splits/dividends/unknown adjustment semantics invalidate that comparison. Record actions and original-versus-outcome vintage differences. Supported symbol changes require append-only ISIN-anchored mapping events; absent mapping/data remain pending rather than removing or replacing the member.

Benchmark uses captured Nifty price-index return, explicitly not TRI if TRI is unavailable. Sector uses matching captured index endpoints where available, otherwise a labeled fixed-industry equal-weight peer basket excluding the stock with all fixed peers present. No sector membership rewrite or silent surviving-peer renormalization. Store log/arithmetic alpha, predicted-relative error only if the prediction actually supplied a matching relative estimate, direction flags, absolute/squared log-return error,50/80interval hits, exact maturity/receipt/source provenance and quality convention.

## Validation, evidence and API semantics

Prospective services aggregate only attached matured genuinely forward records. Default group is canonical version; legacymanual/intraday records and reconstructed historical research require separate filters and never silently pool. Group by horizon/stock/industry/sector/month/regime/confidence/model/protocol; expose total/matured/pending and data failures/coverage, abstention/actionable rates, MAE/RMSE/bias/direction/balancedaccuracy/Brier/logloss/coverage, and available market/sector-relative errors. Counts and missing fields remain explicit.

Forward evidence is INSUFFICIENT_FORWARD_EVIDENCE until every horizon has at least1000matured forecasts,60stocks,10industries,3supportedregimes,60distinct origin sessions, and80%of expected fixed-universe source coverage. Evidence eligibility means enough observations to review, not production eligibility or guaranteed promotion. Research/LOW/abstain imply recommendation_allowed=false; no threshold weakening or frontend BUY/SELL reinterpretation. Future final-window outcomes remain sealed until their separate authorized evaluator opens them.

Read-focused FastAPI and Streamlit consume shared typed application services. Neither request path performs training, walk-forward reconstruction, calibration fitting or gridsearch; default forecast endpoints retrieve sealed saved forecasts. Private raw snapshots/paths and tracebacks do not leave the API. Scheduling is deployment neutral and uses persistent private storage plus explicit commands.

## Append-only metadata amendments
Original forecast and realized-outcome payloads never change. A metadata error is retained, with a hash-bound append-only annotation after source verification. Public scoring excludes unamended invalid clock ordering. A timestamp amendment records later audited acceptance explicitly; it does not claim the original execution happened at that time. Return values and source vintages are unchanged. The initial legacy resolution timestamp issue and its77verified amendments remain in reports/automation/INITIAL_OUTCOME_TIMESTAMP_AUDIT.json and REVIEW.md.
