# Zero-cost public release: preparation and gate

**Status: BLOCKED before cloud provisioning.** This branch prepares a public, read-only research API and a private evidence mirror. No OCI instance, Vercel project, domain, GitHub push, cloud collector, or paid resource has been created. The local laptop remains the only authorized collector. This document is the single deployment checklist and evidence record; do not label the release live until every hosted gate below passes.

## Free-tier decision (checked 2026-10-11)

- **Frontend:** [Vercel Hobby](https://vercel.com/docs/plans/hobby) is $0 for personal, non-commercial use within quotas. It is not a commercial hosting entitlement. The owner must confirm this research project qualifies and configure the frontend root as `frontend/`, with `NEXT_PUBLIC_API_BASE_URL=https://<actual-api-host>` at build time. The browser needs no secret token.
- **Backend candidate:** [OCI Always Free A1](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm) currently grants **1,500 OCPU-hours and 9,000 GB-hours/month** in the home region, equivalent to 2 OCPUs and 12 GB for a full month. An initial **1 OCPU / 3 GB** A1 VM and a **50 GB** boot volume would sit below those compute and [200 GB combined block-volume](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm) limits if no other tenancy resources consume the allocation. OCI can report **out of host capacity**, and inactive free VMs may be reclaimed; neither availability nor uninterrupted operation is guaranteed. Do not upgrade to Pay As You Go or select unlabeled trial/paid resources. Confirm the console shows Always Free eligibility and current tenancy usage before creation.
- **HTTPS:** [Caddy automatic HTTPS](https://caddyserver.com/docs/quick-starts/https) can terminate TLS on the VM using a DNS name and ports 80/443. A [DuckDNS free subdomain](https://www.duckdns.org/spec.jsp) is a possible no-purchase DNS choice, subject to its own availability. The backend container binds only `127.0.0.1:8000`; OCI security rules expose 80/443 and restrict SSH.
- **Cost:** Expected infrastructure charge is **$0/month only if** the owner remains on eligible free plans, uses no paid resource or overage, and stays within all limits. Account signup, capacity, billing verification, DNS, native ARM loading, and real usage have **not** been tested. There is no claim of a forever guarantee.

## Runtime and product boundary

The planned path is browser → Vercel/Next.js → HTTPS/Caddy → one FastAPI worker in a Python 3.12 Debian container → market providers and a private **read-only** evidence mount. `Dockerfile.api` excludes `data/` from its build context. `requirements-api.txt` pins direct dependencies to the locally verified versions; Linux ARM64 wheel availability for XGBoost 3.4.1 and LightGBM 4.7.0 is published on [PyPI XGBoost](https://pypi.org/project/xgboost/) and [PyPI LightGBM](https://pypi.org/project/lightgbm/). A published wheel is **not** proof that these exact frozen bundles load on OCI. Native ARM model loading and representative inference remain mandatory there. GPU is unnecessary. One worker is required for the in-process rate limiter and modest free resources; no horizontal replica is approved.

All ordinary GET research routes are public. The four bounded `/api/v1/analysis/*` POST routes and saved-input `/scenario` POST become public **only** when `STOCKPRO_HOSTED_READ_ONLY=1`; they are stateless and retain the backend's strict input schemas. Request bodies are capped at 16 KiB; provider-heavy paths share a 30/minute single-worker rolling limiter and at most two simultaneous provider-backed requests. Static ticker search and saved-forecast reads do not consume that quota. Every `/api/v1/operations/*` route and internal `/api/v1/system/performance` returns 403 in hosted mode, even with an operator token. Do not set `STOCKPRO_OPERATOR_TOKEN`, `STOCKPRO_API_TOKEN`, or local operator access on the public instance. Browser-local watchlists and portfolio inputs do not synchronize across devices. The current backend has no strategy-backtest execution API; the backtesting page is an explicitly unavailable internal blueprint, so remote strategy execution remains a **real product gap**, not a simulated result.

| Frontend route / workflow | Planned hosted classification | Backend support | Current proof |
|---|---|---|---|
| `/`, `/markets` | PUBLIC_READ | System/model/collection health; market context | Local fixture browser only; external providers untested on VM |
| `/stocks/[ticker]`, `/risk/[ticker]` | PUBLIC_READ | Overview, history, chart, technicals, fundamentals, risk, factors, news | Local API tests; VM/provider data untested |
| `/forecast/[ticker]`, `/validate` | PUBLIC_READ | Saved forecasts, immutable history, analogues, V5 reports, prospective evidence | Restored legacy reads and V5 preservation pass |
| `/screener`, `/compare`, `/portfolio`, `/watchlist` | SAFE_PUBLIC_ANALYSIS | Bounded stateless POSTs; guest inputs stored in the browser | Hosted-mode API boundary tests pass; VM latency untested |
| Saved-input scenario tab | SAFE_PUBLIC_ANALYSIS | Bounded in-memory inference on archived inputs | One local representative inference passed, LOW/abstained |
| `/admin/research-status`, `/admin/research-tools` | OPERATOR / LOCAL_ONLY | Jobs and internal backtesting blueprint | Hosted jobs blocked; no public strategy-backtest API |

No row is marked **fully remote** until a public URL and second-device test exist. The frontend's local fixture browser tests do not establish provider availability or laptop independence.

`GET /api/v1/health` is process liveness. `GET /api/v1/ready` fails closed if the frozen model pointer/bundles, required SQLite databases, the original 388 identities, or the private mirror manifest/hash verification fail. Other hosted product routes return 503 until readiness passes, so absent evidence cannot appear as an empty but normal validation result. Readiness does not depend on an external market provider. A refresh requires a process restart so the new read-only mount is verified before serving. Provider errors remain per-request degraded states. Exact `STOCKPRO_CORS_ORIGINS` must contain only the chosen frontend HTTPS origin; no wildcard or broad preview-domain rule.

## Evidence package and restore

The mirror builder allowlists only `data/prospective_automation/`, `data/research/prospective-india-20261008-v1/`, and `data/v5/`. SQLite uses its online backup API. Logs, locks, `users.json`, secrets, local sessions, caches and unrelated paths are excluded. Every included file receives a SHA-256 entry in `data/EVIDENCE_MIRROR_MANIFEST.json`. Verification checks every file, all three SQLite databases, the preserved 388 payload hashes, forecast/outcome counts, snapshot presence, model ID and `BLOCKED` state. The package must stay private and Git-ignored.

Local commands, from the repository root:

```powershell
python -m scripts.verify_automation_preservation
python -m scripts.evidence_mirror build .stockpro-checkpoints/evidence-mirrors
python -m scripts.evidence_mirror verify .stockpro-checkpoints/evidence-mirrors/<versioned-package>
```

On 2026-10-11 a 97,609,348-byte mirror with 1,097 hashed files was created and copied to a clean local restore directory. Verification passed after copying. The restored FastAPI service returned 200 for legacy validation, a saved forecast, and forecast history; 97 matured outcomes were readable; manifest hashes still matched after those reads. Local preservation verified 1,052 frozen V5 files, 2,904 other preserved files, all original 388 forecasts, and production `BLOCKED`. Counts at this checkpoint: 0 canonical, 388 legacy, 97 matured, 291 pending. Recount at the actual deployment date.

For a future manual refresh: finish local collection → build and verify a new package → retain the old hosted version → transfer privately over SSH to a new versioned VM directory → verify bytes and manifest on the VM → stop the API → atomically change the `current` directory link → start the API with the new read-only mount → require `/api/v1/ready` and representative forecast/validation reads → keep the rollback package. Never merge or write independently to the hosted ledger. Keep local authoritative evidence, the hosted copy and one separately verified backup. Do not commit the package or transfer it through a public repository.

## Deployment sequence once accounts exist

1. Owner confirms personal/non-commercial Vercel Hobby eligibility and an OCI Always Free tenancy with A1 home-region capacity. **Stop if either is unavailable or the console shows a paid/trial-only resource.** Owner supplies only account/instance status and chosen public hostnames; do not paste credentials into chat.
2. On an A1 Linux VM, verify 1 OCPU / 3 GB and 50 GB boot storage fit the tenancy's remaining free allocation. Install Docker and Caddy; copy this branch privately without private `data/`; configure SSH restriction, OS updates and firewall. Build `Dockerfile.api` on the VM and measure image size, startup, idle/peak RAM and provider-backed request times. Load all eight active bundles and run saved-input inference. Stop if native ARM compatibility or memory fails.
3. Privately transfer a freshly verified evidence package to `/var/lib/stockpro/mirrors/<version>/`. Bind only its `data` directory to `/app/data:ro`; set `STOCKPRO_DATA_ROOT=/app/data/prospective_automation`, `STOCKPRO_EVIDENCE_MANIFEST=/app/data/EVIDENCE_MIRROR_MANIFEST.json`, `STOCKPRO_ENV=production`, `STOCKPRO_HOSTED_READ_ONLY=1`, `STOCKPRO_ENABLE_LOCAL_OPERATOR=0`, and an exact `STOCKPRO_CORS_ORIGINS=https://<frontend-host>`. Give the container ephemeral writable `/tmp`; do not put model or ledger state there. Bind port 8000 to loopback only. Caddy forwards the public HTTPS hostname to that loopback port with a proxy timeout above the observed ~20 s factor p95 (initially 60 s). Do not expose port 8000 in OCI rules.
4. Verify the public HTTPS `/api/v1/ready`, CORS, structured failures, operator 403, read-only hashes, and sample user routes. Configure the Vercel Hobby project to build from `frontend/` with `NEXT_PUBLIC_API_BASE_URL` set to that HTTPS backend. Deploy only after the backend passes.
5. In a clean browser on another network/device, test Dashboard → Markets → Stock → Forecast → Validate; Screener → Stock → Compare; Watchlist → Stock → Forecast; Portfolio → Risk → Stock, plus technicals, fundamentals, factors, news and supported scenarios. Confirm research-only/abstain/failed gate, no localhost requests, and laptop-off operation. Record any unavailable provider result honestly. Strategy backtesting stays marked unavailable until a separate bounded Python API exists. Only then consider merging this branch.
